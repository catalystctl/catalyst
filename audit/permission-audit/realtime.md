# Realtime Surface — API Permission Audit

Scope: `catalyst-backend/src/websocket/gateway.ts`, `routes/sse-events.ts`, `routes/console-stream.ts`, `routes/admin-events.ts`, `routes/metrics-stream.ts`, plus the permission primitives they rely on (`lib/permissions.ts`, `lib/permissions-catalog.ts`, `lib/server-access.ts`, `routes/servers/_helpers.ts`, `server.ts` authenticate middleware).

## 1. Executive summary

- 19 channels audited (7 WS message types, 6 SSE routes, 6 fan-out paths). Verdicts: **OK 11 · A-READ-GAP 1 · B-WRITE-LEAK 1 · C-NO-CHECK 4 · E-BROAD 1**, plus **2 D-CATALOG** vocabulary findings.
- The owner's contract holds on the write side: WS power actions (`server_control`), WS console injection (`console_input`), and the gateway re-check behind the SSE command route all require `admin.write` (gateway.ts:3693, 3821, 5435) — `admin.read` cannot write.
- It holds on most of the read side: `admin.read` may subscribe to per-server console (gateway.ts:3575; console-stream.ts:64), per-server events (sse-events.ts:174-181), metrics (metrics-stream.ts:55), and admin entity events (admin-events.ts:124).
- **A-READ-GAP**: the global `all-servers` lifecycle stream excludes `admin.read` from the unfiltered feed (sse-events.ts:202, `isFullAdminRole`); comments at sse-events.ts:191-193 codify a contract that contradicts the owner's.
- **B-WRITE-LEAK (latent)**: `POST /api/servers/:id/console/command` authorizes with `checkIsAdmin(request, 'admin.read')` (console-stream.ts:184) — `admin.read` passes the route gate; only the gateway re-check blocks actual injection.
- **API-key scope bypass**: console-stream routes never call `enforceKeyScope`, so a narrowly-scoped key inherits its owner's console read/write.
- Revocation is strong on the admin stream (60s re-auth, gateway.ts:4917-4952) and per-emit on server streams, but the global all-servers stream never re-authenticates, and the console allowlist admits any `ServerAccess` row (gateway.ts:4276).

## 3. Revocation findings (long-lived streams)

1. **Admin entity-events SSE — re-checked, good.** `reauthAdminSubscribers` (gateway.ts:4917-4952) runs every 60s (interval 4855-4857), re-checks `hasPermission(userId, 'admin.read')` per subscriber (deduped per userId), pushes `admin_permission_revoked` and destroys the hijacked socket (`close` wired from admin-events.ts:154-161). DB errors fail-open (keeps previous result, 4929-4931) — a deliberate availability trade-off.
2. **Per-server events SSE + WS subscriptions — re-checked per emit, good.** `routeToClients` resolves `allowedUsers` on every emit and drops revoked holders for WS (3974-3986), per-server SSE (3991-4001) and global SSE (4011-4017); `invalidateServerAccess` (369-379) + `pruneServerSubscriptions` (385-431) prune proactively on grant/revoke/transfer. Caveat: `console_output`/`resource_stats` use the 30s-TTL cached allowlist (3951), so console/stats revocation lands within ≤30s — fine.
3. **Console SSE — re-checked, but the check is too weak.** The per-emit backstop is `getAllowedUsersForServer(serverId, false, "console.read")`, whose baseline (gateway.ts:4276) is owner + **all** `ServerAccess` userIds. Removing `console.read` from a subuser's row (while keeping the row) never cuts their SSE console stream. Also, the no-argument `pruneServerSubscriptions` path (410-429) builds its work list from `clients` + `sseEventSubscribers` only — the console SSE registry (`sseSubscribers`) is skipped, so global invalidations miss it (the serverId-specific branch at 397-409 does include it, 402).
4. **Global all-servers SSE — never re-checked.** No periodic re-auth for `globalSseSubscribers` (only the 5-min **idle** sweep 4892-4899, which the 25s heartbeat keeps resetting). Unfiltered subscribers get `'deliver'` with no per-emit check on the `pushToGlobalSubscribers` path (4152-4171), and `removeUserServerSubscriptions` only shrinks *scoped* snapshots (449-451) — an unfiltered stream stays live for a demoted admin until the browser disconnects. `routeToClients`-path events *are* re-checked (4017), which is why this is a gap rather than a total hole.
5. **API-key session staleness.** The `authenticate` middleware caches sessions (server.ts:534-546, flushed via cache-bus) and permissions resolve through a 30s TTL with explicit invalidation hooks (permissions-catalog.ts:398-414) — revocation latency is bounded and acceptable; noted for completeness.

## 4. Vocabulary findings + proposed targeted permissions

- **D-CATALOG-1: `server.restart` is a synthetic permission string.** gateway.ts:3702-3716/3738-3742 computes `requiredPermission = "server.restart"` and then special-cases it to *role/access row must hold both `server.start` and `server.stop`*. `"server.restart"` is in no catalog (`permissions-catalog.ts:18-169`, `ALL_SERVER_PERMISSIONS` 238-247) and can never be granted. The REST route mirrors the composite (power.ts:1179-1180), so behavior is consistent — but the vocabulary is misleading. Either add `server.restart` to the catalog + `ALL_SERVER_PERMISSIONS` (and check it directly), or stop materializing the string and keep a comment.
- **D-CATALOG-2: stale duplicate category list.** `lib/permissions.ts:432-546` exports a `PERMISSION_CATEGORIES` that is missing `server.update`, `server.install`, `server.reinstall`, `server.rebuild`, `backup.download` (all present in the canonical `permissions-catalog.ts`). Nothing imports it (only `PERMISSION_PRESETS` is consumed, roles.ts:1048), but any future consumer would present an incomplete permission vocabulary. Delete it or re-export the canonical list.
- **D-3 (design, E-BROAD-lite): any `ServerAccess` row = server-read visibility.** `decideServerAccess` returns `allowed` for any explicit row regardless of `requiredPermission` (lib/server-access.ts:45-47), so a subuser whose row grants only `file.read` may subscribe to the per-server events stream (sse-events.ts:172-180) and is in the fan-out baseline (gateway.ts:4276). `ensureServerAccess` neutralizes this for REST by pre-filtering rows on the required permission (_helpers.ts:517-524), but the raw callers do not. If "every other permission must be narrowly scoped", an empty/one-permission row should not imply lifecycle-event visibility; make the read branch require `server.read` in the row (or in the role set) and keep any-row only for the owner-transfer/UI "shared with me" list.
- **No new permission strings are needed to satisfy the owner's contract.** `admin.read`/`admin.write` already mean read-everything/write-everything in `hasGrant` (permissions.ts:143-149) and `isReadPermission` (130-136). Every realtime fix below is about applying the correct admin bit and the existing targeted perms (`console.read`, `console.write`, `server.start`, `server.stop`, `node.update`) in the right place — plus enforcing API-key scope with the existing `enforceKeyScope` (_helpers.ts:487-493).
- **Credential-surface inconsistency (no verdict class):** sse-events.ts (131-144) and admin-events.ts (110-121) authenticate **session-only** (`auth.api.getSession`), while console-stream.ts (36/154) and metrics-stream.ts (44) use the `authenticate` middleware (session + `catalyst` API keys, server.ts:442-595). An `admin.read` API key can therefore read console and metrics streams but not the events/admin-events streams. Align on `authenticate` for all four (it subsumes sessions).

## 5. Fix list (priority order)

1. **P0 — console-stream.ts:184**: `checkIsAdmin(request, 'admin.read')` → `checkIsAdmin(request, 'admin.write')`. The console-command route is a write channel; today only the gateway re-check (gateway.ts:5435) stops an `admin.read` holder, so the route layer encodes the wrong contract and any future refactor of `sendConsoleCommand` turns it into a live leak.
2. **P0 — sse-events.ts:188-235**: admit `admin.read` to the unfiltered global stream (`isFullAdminRole(rolePerms) \|\| rolePerms.includes('admin.read')` → `allowedServerIds = undefined`), and extend the scoped branch to honor decideServerAccess's `role_permission` branch (global role holding `server.read` → all servers). Rewrite the comments at 189-203 to state the owner's contract. Do **not** rely on the current `recheck-live` compensation (gateway.ts:4174-4178/4011-4017): it is an accident of the G3 gap-fix, misses events whose server row is already gone (e.g. `server_deleted` for foreign servers — only the admin stream carries those), and any refactor of that path silently re-breaks `admin.read`.
3. **P1 — console-stream.ts (GET + POST)**: enforce API-key scope — add `enforceKeyScope(request.user, 'console.read')` (subscribe) and `enforceKeyScope(request.user, 'console.write')` (command), mirroring metrics-stream.ts:54-56. The gateway re-check cannot do this (it only receives `userId`), so it must be at the route.
4. **P1 — gateway.ts:4276 (getAllowedUsersForServer)**: for the `console.read` cache, seed the baseline with owner + only those `ServerAccess` rows whose `permissions` include `console.read`; keep the decideServerAccess loop for role/admin/node paths. This makes per-emit revocation of console.read actually cut console SSE streams.
5. **P1 — gateway.ts:4559-4589 + 4152-4183**: add a 60s re-auth sweeper for unfiltered `globalSseSubscribers` (mirror `reauthAdminSubscribers` 4917-4952): re-check the qualifying grant (`*`/`admin.write`, plus `admin.read` once fix 2 lands) and call an unsubscribe/destroy; register a `close` hook like admin-events.ts does. Optionally also apply the `allowedUsers` check to `'deliver'` decisions on serverId-carrying payloads in `pushToGlobalSubscribers`.
6. **P2 — gateway.ts:410-429 (pruneServerSubscriptions)**: include the `sseSubscribers` (console SSE) registry in the no-argument/global branch, matching the serverId branch at 397-409.
7. **P2 — gateway.ts:5570-5581 (broadcastToAuthenticated)**: scope plugin broadcasts to a serverId or explicit subscriber list, or gate on a declared permission; document the trusted-plugin contract in the plugin SDK if left as-is.
8. **P2 — gateway.ts:3545-3563 (plugin WS dispatch)**: extend `registerPluginWsHandler` (5545-5552) with a required-permissions field enforced by the dispatcher before invoking the handler.
9. **P3 — vocabulary**: resolve D-CATALOG-1 (`server.restart`) and delete/replace the stale `PERMISSION_CATEGORIES` in lib/permissions.ts:432-546.
10. **P3 — credential parity**: switch sse-events.ts and admin-events.ts to the `authenticate` middleware (or otherwise accept API keys) so all realtime read streams accept the same credentials as the REST API.
