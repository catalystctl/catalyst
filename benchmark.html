Why these numbers matter

Benchmarks are not bragging rights — they predict daily cost. A panel serves the same few hot paths thousands of times a day: list servers on every dashboard load, list nodes on every admin ping, fetch a single server on every file/console open.

Throughput → headroom

rps at fixed concurrency tells you how many tabs, users, or automations you can hold before queuing. Catalyst at 400 rps on list paths means a 50-person team with 3 tabs each (≈150 concurrent polls) still has 2× headroom. Ptero at 10–15 rps saturates at ~15 tabs.

Tail latency → perceived speed

p95/p99 is what users actually feel when the DB is warm. 59ms p95 feels instant; 2.3s p95 feels broken. Mean hides outliers; p95 shows the 1-in-20 slow navigation that drives support tickets.

Error rate → truth

Unfair runs showed 99% `429` — fast `429` bodies (8ms) looked like “fast rps” but were failures. Fair runs disable rate-limits (`1M/min` Catalyst bypass, `100k/min` Ptero) and `AUTO_UPDATE_ENABLED=false` so every `200` is real DB + serialize work. Zero `429` = honest numbers.

✓
Rule of thumb: if you have 50 servers, `list-servers` is hit on every login/nav/poll (10–30s). At 416 rps p50 46ms Catalyst serves 50 servers in ~115ms; Ptero needs ~8s at 10 rps. Same for templates: 415 rps p95 56ms for 50 of 261 templates vs Ptero 16 rps p95 1302ms for 5 eggs — the catalog that blocks every server-create modal.

Infra — what you’re actually comparing

Same host, isolated LXCs, pinned resources, no noisy neighbors. Host and containers share the same NVMe and `lxcbr0` bridge, so network is ~0.2ms inside the bridge. Specs frozen in scripts/lxc-lab/config.env.

Method — what “fair” means here

Rate-limits disabled — both sides

Catalyst: catalyst-backend/src/index.ts:562 fairMode → max 1_000_000/min, allowList true bypasses global + per-route, auth.ts:163 rateLimit.enabled=false, mailer.ts:200 1M limits, api-key-service.ts:246 skip refill. Verified BENCHMARK FAIR MODE active.

Pterodactyl: config/http.php 240/720 → 100000 via /root/ptero/.env APP_API_*_RATELIMIT=100000 + docker exec ptero-panel-1 php artisan config:clear cache:clear. Before: 99% 429 Too Many Requests at 20c; after: 0% 429.

External polling suppressed

Catalyst AUTO_UPDATE_ENABLED=false (already in scripts/lxc-lab/compose/backend.yml:69 and /root/catalyst-docker/.env) → services/auto-updater.ts:56 fetch github.com/catalystctl/catalyst/releases/latest never runs during bench (index.ts:1743 skips scheduleUpdateCheck when fairMode). Retention jitter jobs remain but are 60s+ intervals, negligible vs 15s burst. No frontend polling — bench is raw fetch loops in bench.mjs:100 workers.

How to restore

All fair flags are reversible: bash scripts/benchmark/enable-fair.sh --restore sets Catalyst DISABLE_RATE_LIMIT=false and Ptero 240/720 and docker compose up -d && artisan config:clear. Benchmark harness run.sh --fair re-enables automatically if needed.
